# Search Agent — поиск по макетам Figma

Локальный инструмент: загружает структуру макетов Figma в компактную локальную базу и мгновенно
ищет по ней компоненты, фреймы, картинки, слои и тексты — во всех загруженных макетах сразу.
Файлы Figma не изменяются.

- **Поиск** (главная, http://127.0.0.1:8000) — поиск по локальной базе, без запросов к Figma.
- **Настройки** (http://127.0.0.1:8000/settings) — ссылки на макеты, загрузка их в базу, проверка
  обновлений, правила отбора страниц и токен Figma.

Прежние варианты поиска (через API и через плагин) перенесены в `archive/` — см. `archive/README.md`.

## Установка и запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m app
```

Откройте http://127.0.0.1:8000 (порт меняется через `PORT`). В «Настройках», раздел «Подключение к Figma»,
один раз сохраните персональный токен (Figma → Settings → Security → Personal access tokens, scope `file_content:read`).
Токен хранится в локальном `config.json` (в `.gitignore`) и не выводится ни в интерфейсе, ни в логах.

## Автозапуск: сервер работает, только пока открыта страница

```bash
./scripts/install-autostart.sh
```

После этого сервер не нужно запускать вручную. macOS держит порт `127.0.0.1:8000` и запускает сервер,
как только вы открываете `app/static/index.html` или http://127.0.0.1:8000. Открытая страница раз в 5 секунд
сообщает серверу, что она открыта; после закрытия страницы сервер сам завершается через несколько секунд
(если сигнал о закрытии не дошёл — через полторы минуты без сигналов). Незавершённый поиск остановку откладывает.

Журнал: `~/Library/Logs/search-agent.log`. Удалить автозапуск: `./scripts/uninstall-autostart.sh`.
Ручной запуск `.venv/bin/python -m app` по-прежнему работает (порт 8000 должен быть свободен).

## Настройки: ссылки на макеты

Страница http://127.0.0.1:8000/settings. Сверху одна строка: поле ссылки, «Добавить», «Вставить из буфера»
и «Проверить обновления». «Вставить из буфера» видна всегда и активна, когда в буфере ссылка на Figma (если
браузер разрешил читать буфер; до первого разрешения она активна, и первый клик спросит разрешение). Работает и
Cmd+V на странице. Ссылки сохраняются сразу в `config.json` (поле `figma_links`) без служебных параметров вроде
`t=…`; дубли не добавляются. Корзина в строке удаляет ссылку и всё загруженное по ней из базы (с подтверждением).
Подробности по макету — во всплывающей подсказке при наведении на его название.


### Загрузка макетов в локальную базу

У каждой строки справа: **↓** — загрузить в базу (`db/figma.sqlite`), зелёная **✓** — загружено,
синяя **↻** — в Figma есть более новая версия, обновить. Название незагруженного макета выделено красным. Во время загрузки в строке видны этап и прогресс:
«Скачиваем страницы (2 из 10) · скачано 12,4 МБ из ~30 МБ · осталось ~9 с». Сколько всего, Figma заранее не
сообщает — оценка берётся из прошлой загрузки этого макета. Загрузки идут по одной, остальные ждут в очереди.

Кнопка **«Проверить обновления»** лёгким запросом (`/v1/files/:key/meta`) узнаёт версию каждого загруженного
макета в Figma и сравнивает с версией в базе. Версия файла меняется при любой правке — в том числе на страницах,
которые правилами не загружаются.

## Поиск

Поиск по локальной базе, результаты по группам: инстансы компонента (по точному названию компонента или набора
вариантов), мастер-компоненты, фреймы, секции, группы, картинки, фигуры и векторы со своим названием, страницы —
по названию слоя, тексты — по содержимому. Регистр не важен. У каждого результата — файл, путь, размер и
координаты, пометка «скрыт» и ссылка «Открыть в Figma» (открывается сразу в приложении Figma).
Галочка «Не показывать скрытые объекты» исключает слои, скрытые сами или через родителя.
